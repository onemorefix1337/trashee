# trashee для Android

Нативное приложение на Kotlin и Jetpack Compose: тот же клиент Яндекс Музыки, что и на компьютере,
с тем же видом. Воспроизведение идёт через Media3 (ExoPlayer), поэтому музыка играет с выключенным
экраном, а управление есть в уведомлении, на экране блокировки и в наушниках.

## Что есть

- Вход по коду (тот же способ, что на компьютере), токен хранится зашифрованным в Android Keystore.
- Моя волна и бесконечное радио с отзывами для рекомендаций, поиск, любимые треки, плейлисты (свои и
  чужие), альбомы, исполнители, закрепленное из официального приложения.
- Полноэкранный плеер: обложка, акцентный цвет по обложке, перемотка, перемешивание и повтор,
  «Нравится», «Не нравится», «Похожие», очередь.
- Тексты песен: сначала Яндекс, если его нет, то LRCLIB и lyrics.ovh, с синхронизацией или без.
  Под текстом написан источник.
- Качество звука: экономное, высокое, без потерь. Зашифрованный поток расшифровывается на лету.
- Без ожидания между треками: со второй половины трека следующий скачивается заранее
  (в настройках это можно выключить).
- Сохранение для прослушивания без сети: плейлист, альбом или любимые треки целиком, вместе с
  текстами и обложками. Без сети приложение открывается с сохранённым и само находит связь, когда
  она появляется.
- Отдельный трек можно скачать файлом: меню трека, «Скачать файл». Он попадёт в «Музыка/trashee».

Не сделано: визуализатор, эквалайзер, обновление изнутри приложения, виджет.

## Сборка

Нужны Android Studio (или Android SDK с платформой 37) и JDK 17 или новее. Минимальная версия Android — 10.

```bash
cd trashee_android
./gradlew assembleDebug
```

Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`. Установить на подключённый телефон:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Проверки без устройства (подпись запросов, расшифровка, разбор LRC и поиск текстов сверены со
значениями из TypeScript-версии):

```bash
./gradlew testDebugUnitTest
```

### Проверка на эмуляторе без аккаунта

Отладочную сборку можно направить на свой тестовый сервер, который изображает Яндекс (адрес
`10.0.2.2` — это компьютер, на котором запущен эмулятор):

```bash
./gradlew assembleDebug -PapiBase=http://10.0.2.2:8787 -PoauthBase=http://10.0.2.2:8787
```

Обычный http разрешён только в отладочной сборке и только для `10.0.2.2` и `localhost`. Выпускная
сборка ходит исключительно по https.

`-PminifyDebug` включает сжатие кода в отладочной сборке, чтобы проверить, что R8 ничего лишнего не
вырезал.

## Выпуск

Выпускной APK подписывается собственным ключом, и этот ключ нужно хранить: без него уже
установленное приложение нельзя обновить. Файлы `*.jks`, `*.keystore` и `keystore.properties`
исключены из git.

**Локально.** Положи ключ куда угодно и опиши его в `trashee_android/keystore.properties`:

```properties
storeFile=/путь/к/trashee-android-release.jks
storePassword=...
keyAlias=trashee
keyPassword=...
```

```bash
./gradlew assembleRelease -PversionName=0.1.0
```

Версия берётся из `-PversionName`, а код версии из неё считается сам (1.2.3 станет 10203).

**На GitHub.** Нужны четыре секрета репозитория: `ANDROID_KEYSTORE_B64` (ключ в base64, например
`base64 -i trashee-android-release.jks | pbcopy`), `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`
и `ANDROID_KEY_PASSWORD`. Потом тег `android-v0.1.0` запускает сборку и создаёт черновик релиза с APK и
`SHA256SUMS.txt`. Опубликовать его нужно так, чтобы он не стал «последним» релизом, иначе сломаются
проверка обновлений на компьютере и сайт:

```bash
gh release edit android-v0.1.0 --draft=false --latest=false
```

## Обновления

При запуске приложение смотрит список релизов на GitHub и берёт самый новый с тегом `android-v*`.
Если он новее установленной версии, показывается окно с размытым фоном: обновить, напомнить позже
(на сутки) или пропустить эту версию. APK скачивается, сверяется с `SHA256SUMS.txt` и передаётся
системному установщику. Android не даёт ставить обновления молча, поэтому нужно один раз разрешить
установку из trashee и нажать «Обновить» в системном окне. После установки приходит уведомление,
по нему открывается новая версия.

Обновить можно только приложение, подписанное тем же ключом. Отладочная сборка подписана другим
ключом, поэтому поверх неё выпускную версию нужно ставить после удаления отладочной.

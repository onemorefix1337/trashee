# Синхронизация компьютера и телефона

Работает только в одной локальной сети. Компьютер (приложение trashee) выступает сервером, телефон
подключается к нему. Токен Яндекса между устройствами не передаётся: летят только названия треков, их
номера, очередь и позиция.

Код сервера: `src/main/sync/server.ts`. Общие типы и проверки: `src/shared/sync.ts`. Подпись запросов:
`src/main/sync/crypto.ts`. Клиент на телефоне: `trashee_android/app/src/main/java/app/trashee/sync/`.
Обе реализации проверяются одними и теми же контрольными значениями (`crypto.test.ts` и `SyncTest.kt`).

## Что происходит

1. **Поиск.** Телефон рассылает UDP-пакет `TRASHEE-DISCOVER 1` на порт 47875. Компьютер отвечает JSON
   `{"app":"trashee","v":1,"id":"…","name":"MacBook","port":47874}`. Если пакеты не доходят (роутер
   изолирует устройства), адрес `ip:порт` вводится руками. Компьютер показывает его в настройках.
2. **Пара.** В настройках компьютера «Показать код» открывает окно на две минуты и показывает шесть цифр.
   Телефон посылает `POST /pair` с `{deviceId, name, platform, nonce, proof}`, где
   `proof = HMAC-SHA256(код, "pair|deviceId|nonce")`. Сам код по сети не идёт. В ответ компьютер отдаёт
   токен, сложенный (XOR) с `HMAC-SHA256(код, "tok|nonce")`. После пяти неверных попыток код сгорает,
   после успешной пары тоже.
3. **Запросы.** Все остальные запросы подписаны токеном: заголовки `x-device`, `x-time` (мс), `x-nonce`,
   `x-sig = HMAC-SHA256(токен, "METHOD\nпуть\nвремя\nnonce\nsha256(тело)")`. Сервер принимает время с
   разницей не больше двух минут и не принимает один nonce дважды.
4. **Поток событий.** `GET /events` (Server-Sent Events) остаётся открытым. Сервер шлёт: `hello`
   (время компьютера, чтобы телефон знал разницу часов), `host` (что играет на компьютере), `devices`
   (другие телефоны), `command`, `handoff`, `pull` и `ping` раз в 20 секунд. Потеряв связь, телефон
   переподключается с растущей паузой и ищет компьютер заново по его `id`, если адрес сменился.

## Запросы телефона

| Запрос                                   | Для чего                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------ |
| `POST /state` `NowPlaying`               | Рассказать, что играет на телефоне. Время берётся по часам компьютера.   |
| `POST /command` `{target, command}`      | Нажать кнопку на устройстве: `toggle play pause next prev seek volume like dislike`. |
| `POST /handoff` `{target, handoff}`      | Передать очередь: id треков вокруг текущего, позиция, играет ли.         |
| `POST /pull` `{target}`                  | Попросить устройство передать музыку сюда.                               |

`target` это `host` (компьютер) или `deviceId` другого телефона: сервер пересылает его по потоку событий.

## Передача

Отправитель шлёт окно очереди: пять уже сыгранных треков и сто пятьдесят следующих (только id), первые
три трека с данными и позицию. Получатель находит треки по id в своём аккаунте, ставит очередь на нужный
трек и включает его на то же место, добавив время, которое ушло на поиск. После передачи отправитель
ставит на паузу.

## Что не защищено

Код сопряжения короткий, и тот, кто подслушает именно эту пару, сможет перебрать его оффлайн. Окно
сопряжения открыто две минуты и закрывается после первого успеха. Названия треков и команды идут по сети
без шифрования, но подделать запрос без токена нельзя, а повторить чужой нельзя из-за времени и nonce.
Это защита домашней сети, а не интернета: порт не стоит открывать наружу.
